# pinax (@toxicwind/pinax) — design (2026-09-30; Tack renamed to Pinax, moved under flock)

## The disease

The same hardcoded provider→models lists existed in four places:

1. `estate/mesh/router/estate-scripts-router/estate-scripts-router-ts/router_config.ts` — `PROVIDER_MODELS`
   (curated arrays) unioned with `LIVE_MODELS` (discovery), curated first.
   Discovery could only ADD; dead curated ids stayed routable forever.
2. `herd/internal/astmatrix/providers.go` (Go) — hardcoded
   per-provider lists + alias map (35 entries duplicated the canonical catalog),
   including the same 4 dead groq ids. Deduped 2026-09-30: only true herd-local
   extras remain; the rest is generated from @toxicwind/pinax.
3. `research/add_groq.py`, `research/check_providers.py` (Python) — hardcoded
   groq/provider model lists.
4. TAU `pi-catalog` — 86 KDL-authored provider entries under
   `packages/catalog/src/compat/rules/providers/` + compiled
   `src/compat/providers.ts` (replaced by @toxicwind/pinax 2026-09-30).

Production symptom: 4 of 6 groq ids 404'd until a human noticed (groq
re-verification 2026-09-30). the Architect: "there shouldn't be hardcoding of any
model names in the provider -> what models they have thing."

## The cure

One Bun/TypeScript package — `pinax` (`@toxicwind/pinax`)
in the estate monorepo — as the single source of truth. Consumers:

- **estate-scripts-router-ts**: imports the TS package directly.
- **tau** (`estate/tau`, toxicwind/tau): @toxicwind/pinax is the main-class provider
  system — it replaced pi-catalog's KDL provider entries, provider-models data,
  and discovery.
- **herd (Go)**: cannot import TS → consumes `generated/providers.go`,
  checked in, regenerated by `bun run build`, never hand-edited. The sync
  test regenerates into a temp dir and diffs byte-for-byte; a stale artifact
  fails the suite.
- **Python research scripts**: consume `generated/providers.json`.

After landing, the hardcoded lists in `router_config.ts`, herd's
`providers.go`, and the research scripts become generated-or-imported, not
hand-maintained.

## Serving semantics

The catalog keeps, per provider: `live` (last successful listing), `serving`
(derived), `everDiscovered`, `miss` (id → consecutive successful-refresh
misses), `quarantine` (id → {reason, since}), `lastOk`/`lastError`.

- **Cold start**: `servingModels()` = seeds − quarantine − dead.
- **First success**: `everDiscovered=true`; seeds go inert; serving = live −
  quarantine − dead.
- **Miss accounting**: on each successful refresh, ids in (prevLive ∪ miss
  keys) but absent from the new listing get miss+1. At
  `PRUNE_AFTER_MISSES=2` → quarantine (`vanished-from-live-listing`).
  Serving includes ids with miss < 2, so a single missed refresh never
  drops a model from routing.
- **Serve 404** (`noteServe404`): immediate quarantine, dropped from serving.
- **Re-admission**: any id present in a new successful listing leaves
  quarantine (except `dead-list`, which discovery can never clear) and has
  its miss counter reset.
- **Dead list**: permanent EOL tier. Never served, never re-admitted.
- **Ordering**: `orderedServing()` stable-sorts by seed order first (UX hint),
  then discovery order. Seeds influence order, never membership.

## Adapters (all /models endpoint forms)

| Adapter | Request | Parses |
|---|---|---|
| `openai` | `GET {base}/models`, Bearer | `{ data: [{ id }] }` |
| `mistral` | `GET {base}/v1/models`, Bearer | `{ object:"list", data:[{id}] }` (pinned separately for future divergence) |
| `google-v1beta` | `GET {base}/v1beta/models`, `?key=` or `x-goog-api-key` | `{ models: [{ name:"models/…" }] }`, prefix stripped |
| `static` | no fetch | `def.staticModels` (herd roles); counts as successful discovery |
| `none` | no fetch | `[]` + reason (kimi-auto); counts as successful discovery |

Auth styles: `bearer` | `x-api-key` | `query-key` | `none`, plus
`modelsPath`/`headerName`/`queryParam`/`extraHeaders` overrides per provider.
The next odd shape gets an adapter, not a special case.

## Persistence

- v2 shape: `{ version: 2, providers: { name: { live, everDiscovered, miss,
  quarantine, lastOk, lastError } }, updatedAt }`.
- v1 migration: legacy `{ live: { provider: [...] }, meta }` → any provider
  with a persisted live listing counts as discovered; serving re-derived
  (dead-filtered) so stale arrays can't resurrect dead ids.
- Atomic writes: same-dir temp + fsync + rename.

## Codegen contract

`src/data.ts` is the source of truth. `bun run build` emits:

- `generated/providers.json` — `$schema: estate-pinax/v1`, providers,
  seeds (+ contract text), aliases, deadIds (+ contract text), provenance.
- `generated/providers.go` — `package astmatrix`, `ProviderDef` struct,
  `ProviderCatalogDefs`, `ProviderCatalogSeeds`, `ProviderCatalogStaticModels`,
  `ProviderCatalogAliases`, `ProviderCatalogDeadIDs`, DO-NOT-EDIT header.

herd's merge/selection LOGIC stays hand-written and reads these tables; only
the data is generated. The Go file's package/symbol names were chosen from
the herd audit to be a drop-in data replacement.

## Migration map

- `router_config.ts`: `PROVIDER_MODELS` → re-exported seeds from the package
  (documented cold-start only); `catalogModelsFor()`/`firstModelFor()` delegate
  to the catalog; `DEAD_MODEL_IDS` → package dead tier; `CODING` → package
  aliases.
- `router_live_models.ts`: scheduler calls `discover()` per provider and
  `catalog.applyDiscovery()`; failures leave state untouched.
- `router_matrix.ts` `noteEntitlement404()`: also `catalog.noteServe404()`.
- `router.ts` `/v1/models`: source tags `live`/`seed`; `/status`: quarantine
  counts per provider.
- `router_ui.ts`: counts from the serving set.
- herd `providers.go`: replaced by `generated/providers.go` (separate ranch
  commit); merge loop untouched, reads generated tables.
- `research/add_groq.py`, `check_providers.py`: read `generated/providers.json`
  instead of hardcoded lists (ranch commit).
- tau pi-catalog: @toxicwind/pinax replaced the KDL provider entries entirely
  (per Pip's trace of `currentModelRegistry`'s origin).

## Borrowed patterns (Rook 2026-09-30)

Ranked GitHub search via pattern-borrow.ts; all patterns sourced from direct
code reads. These shaped the quarantine, refresh, and codegen design above.

1. **anomalyco/models.dev** (Bun/TS, #1): per-shape sync adapters
   (`SyncProvider`: fetch/parse/translate per endpoint shape), zod-validated
   parsing (OpenAI `{data:[{id}]}`, Google `{models:[{name}]}` + `models/`
   prefix strip, Anthropic paginated with `has_more` guard), churn guards
   (`MAX_CREATED/M_DELETED/MODEL_CHURN` block auto-merge for human review),
   deterministic catalog→consumer emitters. Borrowed: adapter interface,
   per-shape parsing, deterministic codegen.

2. **BerriAI/litellm** (Rust catalog crate, #2): provenance
   (`{source, revision, ETag}`), shrink guards (min-count + reference-ratio
   reject suspiciously-shrunken catalogs), alias-collision detection,
   schema generator that fails closed on unclassified keys, `--check` mode
   for CI sync. Borrowed: provenance in JSON, `--check` byte-diff test,
   fail-closed on unknown.

3. **ENTERPILOT/GoModel** (#3): stale-not-dead inventory (failed probe
   demotes provider to back of resolution order instead of wiping),
   refresh report semantics (`partial` keeps previous inventory),
   single-flight refresh guard, ETag/304 preservation, parse-before-swap
   (never replace state on failure). Borrowed: stale-serve on failure,
   singleflight, mtime/ETag-aware refresh.

4. **Autobyteus** (design doc, #4): provider-scoped reload (replace on
   success, preserve on failure), "discovery keeps only normalized identity
   + recognized metadata — credentials never enter persisted projections".
   Borrowed: replace-on-success / preserve-on-failure, no secrets in state.

5. **prismeai + llm-usage-bar** (#5): quarantine ≠ delete (hidden vs
   disabled vs deleted lifecycle), `RefreshOutcome` ledger (upsert, never
   delete-first; a failed fetch must not empty the catalog). Borrowed:
   two-strike quarantine with re-admission, refresh ledger in logs.

What was skipped: freellm (static hardwired arrays, no discovery); models.dev
GitHub-issues workflow and per-consumer script sprawl (one `providers.go`
generator); litellm pricing schema and Python/Rust duplication; GoModel
runtime config surface.
